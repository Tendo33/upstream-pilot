# 运营扩展规划

Upstream Pilot 可以增加面向 Sub2API 运营人员的扩展模块，但扩展模块与上游质量控制保持独立。默认只读，写操作必须单独启用并留下审计记录。

## 充值审计

第一阶段读取 Sub2API 已有充值记录，提供时间、用户、状态、支付渠道、金额、币种和订单号的筛选与汇总。漏斗只使用明确的订单状态计算：创建、待支付、已支付、已入账、失败和退款。缺少账务字段时显示未知，不从余额变化或请求日志推测充值。

第二阶段增加异常视图，例如支付成功但未入账、重复订单、退款后余额未回收。该模块不修改账务记录，账务修复仍在 Sub2API 中完成。

## 兑换码

兑换码生成、过期、批量筛选和删除属于写操作，必须使用 Sub2API 官方管理接口或经过确认的独立适配器，不直接写主库。每批操作保存操作者、数量、额度、币种、过期时间和返回的业务 ID；删除默认只允许撤销未兑换且未过期的码，并要求二次确认。

## 运营风控

风险分析先做只读：高频请求、额度消耗异常、共享 IP、短期注册集中、Token 轮换和封禁历史。结果是风险线索，不自动封禁用户。需要显示时间窗口、证据数量、数据来源和采集盲区，避免把代理出口或共享网络误判为同一身份。

## AbuseHub 连接器

AbuseHub 作为可选连接器单独配置 URL、节点名称、密钥和拉取间隔。Pilot 只拉取通报并缓存脱敏匹配线索，匹配 email、OAuth、IP 或其他身份线索后进入人工复核队列，不自动封禁或广播。连接器故障不得影响质量采集和调度。

## 实施顺序

1. 充值审计只读页面和统一筛选接口。
2. 运营风控只读分析与风险证据页。
3. 兑换码通过官方接口实现带确认的生成和撤销。
4. AbuseHub 可选连接器和人工复核队列。

每个模块都必须单独标识“数据来源、更新时间、权限、只读/写入状态和未知原因”，并纳入 Docker Compose 的可选配置。
