# 使用手册

## 接入

在站点页填写 Sub2API 根地址与管理 Key，同步账号和组。连接本机或可信内网时，才启用 `PILOT_ALLOW_PRIVATE_UPSTREAMS=true`。多租户公网实例不应随意开放内网访问。

在质量页选择实际支持的测试模型，设置探测间隔、超时和采购倍率采集。统计窗口与最新证据有效期分别设置；间隔应与所需样本量和模型的正常耗时匹配。

## 控制

- 观察模式记录建议，不发送自动参数修改。
- 自动优先级按组内顺序调整；数字较大表示较低优先级。
- 停调只在明确启用、确认硬故障并有有效健康备用时尝试。
- 并发上限和负载系数分别开启，按风险级别降低并恢复。
- 外部人工修改会触发冲突，避免自动覆盖。

“还原基准并停止”恢复受管理的优先级和容量。调度开关仍在账号页单独控制。“保留当前值并停止”解除接管并采用现值，不进行参数还原。待确认写回也保留解除入口。

## 成本与通知

采购倍率记录供应商成本及变化。首次有效值作为比较基准；接受新基准需要当前价格仍有效且没有变化，绝对成本上限仍生效。质量规则不改用户售价；分组倍率公式单独保存或手动应用。

通知支持通用 JSON Webhook 和企业微信。通用消息包含 `event_id`，接收端应去重。投递失败最多尝试五次；HTTP 成功但回执保存失败时可能重复投递，不能假设严格 exactly-once。

## 运维判断

“最近一次探测成功”不等于全部质量正常。检查质量页的风险、证据年龄、接管状态和写回错误。来源、凭据或映射更换后，应暂停自动控制并重新采集证据，确认历史数据已不再影响新来源；当前身份隔离缺口见 `REVIEW.md`。

进入生产前验证真实请求、流式输出、工具调用、会话绑定和实际路由分布。多个账号也可能来自同一供应商，健康账号数量不代表独立容量。

## 换源和控制事件

更换地址、密钥、模型映射或计费来源后，质量页会等待新来源证据。历史记录仍可查看，旧零余额和旧探测不参与新来源的控制。升级数据库后也需要重新采集，不能用旧缓存判断已经恢复。

“原生候选：资格未知”表示目标接口没有提供足够的运行约束，或当前账号类型尚未适配。该账号可以继续由 Sub2API 调度，但 Pilot 不把它认证为暂停其他账号所依赖的备用。原生额度耗尽的周期即使看起来已到重置时间，也要等待新读回确认。

“事件与通知”分开展示主动探测、真实请求、余额、采购倍率和控制写回问题。供应商质量正常时仍可能存在管理接口故障。控制失败查看页面原因与动作历史；超过五分钟的待确认控制有独立事件。修复权限或网络后重试评估，控制器会核对旧动作，确认或撤销未执行部分，恢复通知只发送一次。不要为了清除提示而直接修改本地所有权记录。
