# Upstream Pilot 整仓审查

审查范围覆盖 Go API、认证与权限、后台任务、采集与调度、数据持久化、React 页面、部署脚本、依赖与代码来源。包含代码检查、隔离数据库复现、自动测试及本机界面验证，不是生产流量认证。审查日期：2026-09-04。

> 续审已增加原生冷却资格、认证错误过滤、控制告警与排序稳定性等发现，最新辅助能力路线见 [Sub2API 辅助能力续审](SUB2API_COMPANION_REVIEW.md)。本文保留初次整仓审查的基线结论。

## 结论

工程健康度暂评 **68/100**：核心控制链路已有测试，但仍存在一个已复现的来源身份缺口，以及规模和兼容字段方面的技术债。默认观察模式适合继续评估，不建议在未处理来源变更问题前进行无人值守的生产自动接管。

本项目不是完全原创代码。命名前的来源比较发现，底座导入的 123 个文件中有 80 个逐字节未改。当前目录、文档和品牌已经独立，不改变代码来源。完整口径见 `PROVENANCE.md`。

## 已确认、尚未解决

### [P1] 来源更换后，质量引擎仍可能消费旧来源余额

位置：[`quality_storage.go`](../internal/app/quality_storage.go#L75)，对照 [`account_balances.go`](../internal/app/account_balances.go#L85)。

账号余额 API 会核对缓存 key，key 包含来源地址和凭据指纹；质量快照只按 account_id、status 和 checked_at 判断余额有效性，没有核对同一身份。仅有时间有效性不足以保证证据属于当前来源。

隔离复现：先为旧来源保存有效的零余额，再更换来源 URL 和凭据指纹。账号余额 API 正确返回 pending，但质量引擎仍用旧零余额得出 tier=2，并实际把模拟账号设为不可调度。请求与模型探测可以成功，仍会发生这个错误。

建议：统一余额、成本和探测证据的身份标识；来源变更时使不匹配的证据失效。持久化和消费都核对配置/来源代次，覆盖来源切换期间的在途采集。修复前更换来源应停止自动控制，重新采集并检查证据后再恢复。

### [P2] 大库存下存在串行查询和二次方规划成本

位置：[`engine_api.go`](../internal/app/engine_api.go#L123)、[`quality_api.go`](../internal/app/quality_api.go)、[`planner.go`](../internal/quality/planner.go#L102)。

分组接口逐账号构造质量视图，每个视图有多次查询；页面定时同时读取质量、分组和站点。规划器对每个池的候选两两比较并保存关系。这是代码可确认的复杂度风险；本轮没有生产规模压测，不能给出未经测量的容量上限。

建议：先批量加载不可变快照，缓存低频元数据；对大池测量 SQL 数量、延迟、内存和锁占用，再精简排序关系。不要仅增加后台 worker 数量掩盖等待。

### [P2] 兼容数据和已停用控制路径仍需收敛

位置：[`accounts.go`](../internal/app/accounts.go#L1145)、[`overview.go`](../internal/app/overview.go#L23)、[`cache_rate.go`](../internal/app/cache_rate.go)。

底座的 priority_enabled、guard 字段及旧排序辅助函数仍存在，正式写回已委托质量引擎。旧总览按最近一次探测统计，并不等于质量风险统计。静态检查与隔离复现均确认了两套口径。

本次已移除账号页“固定/自动排序”的误导标签，并将总览“运行健康”改为“最近探测成功”。这解决了直接的展示误导，但兼容字段和未使用辅助逻辑还没有完成清理；后续应通过迁移和调用图明确保留范围，不能把旧算法的单元测试当成当前调度引擎覆盖。

## 安全与依赖审查

认证使用服务端会话，修改请求校验 CSRF，主要资源查询限定 owner。管理员变更事务会重新确认权限。外部 HTTP 默认限制内网地址并禁用重定向，前端以文本方式呈现常规数据；未在本轮抽查中发现新的明确越权入口。这不等于完整渗透测试。

初次 npm audit 报告 nanoid 和 React Router 相关告警；已升级到对应修复版本。最后一次 npm audit 联网复查遭遇官方审计端点超时，因此不声称最终 npm audit 全绿。官方修复说明：[nanoid](https://github.com/advisories/GHSA-2v37-7h3g-55p8)、[React Router](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6)。

更新后的 govulncheck 未报告被本项目调用的漏洞函数，仍有未调用子包的模块级提示，不能等同于依赖树没有任何公告。Git 历史扫描命中的是公开测试用的固定密钥材料；实际 `.env`、本机凭据与运行数据均不在提交范围。扫描是风险检查，不是凭据绝对不存在的数学证明。

## 验证与边界

本机使用 `go test -race -count=1 -json ./...` 得到 **181 个顶层测试、283 个含子用例的通过事件，零失败、零跳过用例**；前端构建和 go vet 通过。

正式测试覆盖风险恢复、过期证据、旧意图取消、部分写回确认、事务失败重试、相关分组隔离、真实首字取样与容量还原，并新增身份标识迁移验证。版本与品牌变更后重新执行构建和非缓存 race 测试，最终结果见 CI 与发布记录。

本轮剩余来源问题的复现使用单独 schema 和 httptest 模拟端点，不触及生产。模拟器没有完整复制 Sub2API 的负载权重、粘性选择和请求重试；真实供应商的余额单位、价格结构与容量独立性需要接入验收。
