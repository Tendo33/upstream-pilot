# Upstream Pilot 整仓审查

审查日期：2026-09-05。范围覆盖 Go API、PostgreSQL 迁移、Sub2API/NewAPI 客户端、后台任务、调度写回、React 控制台、依赖、来源与文档。结论只针对本仓库和本地隔离验证，不代表生产 SLA。

## 当前结论

项目已具备作为 Sub2API 辅助控制面的完整工程形态：来源证据隔离、原生资格、错误分类、稳定调度、分组/账号协议探测、供应商故障域、统一成本、余额续航、批量采集、请求去重、效果观察和自身健康已形成闭环。默认仍为观察模式；停调和容量写回需独立开启。

目前还不能宣布全部验收完成。目标 Sub2API 测试实例已启动并通过 `/health`，但它自身要求管理员接受《部署与运营合规承诺》后才允许创建测试组、账号和 Key。该电子承诺未获用户授权，管理写入返回 423；本项目没有绕过门槛。因此“目标 Sub2API 真实入口”这一项仍未完成，模拟器结果不能替代它。

项目是 S2AM-GO 的 MIT 派生项目，不是完全原创重写。当前名称、模块、运行配置、文档和新增控制能力由本项目维护；原作者声明与依赖许可证保留。没有导入 Guardian 源码。完整来源见 `PROVENANCE.md`。

## 已关闭的高风险问题

- 来源地址、凭据、模型映射和计费来源使用独立 `source_generation`；余额 key、价格、探测、真实请求和在途结果都核对当前代次。旧数据保留审计，不进入新路由。
- Sub2API 冷却、限流、过载、到期、额度、模型与组成员资格单独判断；接口缺字段时为 unknown，不能认证为停调备用。
- `account_auth/401` 计入上游认证错误；客户认证、参数、路由、供应商、采集和控制错误分开。控制失败与恢复进入去重事件和通知 outbox。
- 控制意图先落库，副作用读回后确认。来源、站点地址、配置、证据、人工值或租约变化会停止写回。还原只处理仍由 Pilot 拥有的字段。
- 健康候选有绝对/相对改善阈值、保持期、灰度、每轮数量和观察窗口；硬故障与已拥有暂停的恢复可及时处理。

## 分组服务与协议

Chat Completions、Responses 和 Messages 支持文本、流式与工具结构合成探测。工具只验证 `pilot_ping` 的固定 JSON，不执行现实动作。每次最多一个 POST，不自动重试；读取大小、超时、请求、token 和可确定金额均受限。心跳不计首内容，非流式总耗时不充当首内容，缺少终止标记不算完成。

分组档案走配置的用户入口和专用 Key；账号档案只支持 API Key，按需从 Sub2API 导出来源凭据并核对地址与指纹，不保存副本。账号档案是 Pilot 直连供应商的视角，不代表 Sub2API 的代理、Header 或模型映射路径。

真实请求按站点代次、group_id 与 request_id 归并。明确最终成功可覆盖中间重试错误；矛盾终态变为 conflict；流式完成或最终标志缺失时保持 unknown。合成 request/session ID 从用户结果和真实用量结构中排除。

## 供应商、容量和成本

供应商、失效域和共享额度池需要操作员确认，并绑定来源代次。相同供应商、失效域、额度池或 URL+凭据进入同一故障组件。停调保护按不同组件计数，同一供应商的多个 Key 不会增加独立备用数。

目标 Sub2API 在并发读取失败时也可能返回 0，因此 0 不证明空闲。只有接口同时明确报告并发读取成功、当前并发和排队深度时，才显示已验证空闲槽位；其他情况保持 unknown。非零容量门槛不会由未知容量通过。

模型价格卡区分输入、输出、缓存读写、币种、换算、token 单位、倍率是否另乘、充值比例、依据和有效期。跨上游排序只采用同一分组流量结构和共同 USD/百万 tokens 基础；缺价格、缓存价、换算、用量样本或有效期时不可比较。用户售价不在自动控制字段中。

余额续航至少需要四个同来源、同单位样本、十五分钟跨度和最近十分钟内的读数。充值、重置、单位变化或高波动会清空预测；结果给出近期速率区间，不伪装成账单保证。

## 采集与自身健康

真实请求和 usage 按站点批量拉取，最多三页、每页 100 条；截断和无法关联记录单独显示。低频元数据与动态质量证据分开。健康且有足量真实首内容数据时可降低合成探测频率；异常和冷启动仅在每日预算还有普通周期余量时加快。

通用任务租约有 UUID 拥有者、两分钟有效期、30 秒续租和丢失取消。站点库存、控制、请求和 usage 共用站点资源租约及 advisory lock，避免重复领取和锁顺序死锁。每次执行写入 `task_runs`，控制整轮限制为 90 秒。运行页显示站点积压、采集状态、任务结果、数据库连接/操作和管理员可见的进程负载。

浏览器曾发现 usage 与 traffic 并发触发 PostgreSQL 40P01；统一站点资源锁后，最新运行态的 usage、traffic-site、inventory、probe、rate 和 reconcile 均成功，日志未再出现死锁。
