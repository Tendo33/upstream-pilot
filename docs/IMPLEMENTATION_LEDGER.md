## 本次修复

1. 分别读取请求明细、上游尝试错误和最终请求错误，窗口一致，每类最多 300 条；同一失败不在供应商统计中重复计算。
2. 最终失败按专用接口确认；中间 503 后成功不能误记为最终失败。未提供流结束证据的记录保持未确认。
3. 接口失效和截断保留已观察到的失败；不完整成功样本不认证健康、不解除旧风险，也不作为降低主动探测频率的依据。
4. 备用统计加入原生资格时效、质量评估时效和来源代次；只有真实请求证据时也保留评估使用的样本时间。
5. 运行页集中显示最终请求结果、逐接口采集状态和采购声明覆盖。采购声明不自动改写成本或余额。
6. 修正任务“上次成功”按资源查询，避免同类任务在不同站点间串用时间。

## 消息中心统一（迁移 033）

- 质量、余额、采购与控制事件共用一个消息中心，旧两个页面跳转到 `/notifications`。
- 飞书 / Lark、企业微信、通用 Webhook 有独立订阅与回执。URL/签名密钥加密且不回显，消息投递禁止跨地址重定向；业务失败不会标成送达。
- 原质量/余额渠道及规则通过迁移保留，旧密文用途不改变；自动识别通用渠道保留原三字段 JSON 格式。
- 新渠道默认停用，只接收新事件；旧来源、改动后的渠道和过期事件停止旧投递。每渠道五次重试，UUID 租约阻止迟到回执覆盖新状态。
- 默认累计涨价 5%、冷却 60 分钟；低余额使用新鲜且来源匹配的读数，恢复与单位/来源变化区分。
- 全量 PostgreSQL 竞态测试、500 账号规模门槛、前端构建通过；新增回归覆盖迁移、签名与业务回执、独立失败重试、在途改渠道、迟到回执、来源变化、涨价累计与余额恢复。
- 浏览器使用本机模拟接收端验证保存、密钥不回显、成功/503 重试展示和旧页面跳转；没有向生产飞书群发送消息。生产部署仍需可用 SSH 入口与目标实例验收。
