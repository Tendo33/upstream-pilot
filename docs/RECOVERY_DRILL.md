# 故障恢复演练

本演练只使用本机模拟器和隔离 PostgreSQL，不连接真实供应商，不发送生产请求。

## 启动

```bash
make demo-upstream
PILOT_TEST_DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:5432/TEST_DB?sslmode=disable' go test -race -count=1 ./...
```

在另一个终端启动 Pilot，并使用独立 `.env`。确认页面中的站点地址为
`http://127.0.0.1:33888`，站点和账号均属于演练数据库。

## 故障注入

```bash
curl -X POST http://127.0.0.1:33888/control/101 \
  -H 'Content-Type: application/json' \
  -d '{"probe_success":false,"probe_delay_ms":0}'
```

等待一轮探测后，在“质量”和“消息中心”确认：风险升级、失败原因、采集状态和控制状态分开显示。若启用了自动优先级，动作必须先出现待确认记录；不能只凭本地状态宣称已写回。

## 恢复

```bash
curl -X POST http://127.0.0.1:33888/control/101 \
  -H 'Content-Type: application/json' \
  -d '{"probe_success":true,"probe_delay_ms":1500,"billing_rate":2}'
```

确认后续探测使用当前来源代次，风险进入恢复计数并按保持期关闭；旧来源或旧任务的迟到结果不能覆盖新状态。若控制写回在故障期间失败，先在动作历史中核对已执行字段，再使用“还原基准并停止”或“保留当前值并停止”。

## 租约与重复任务

运行页应能看到任务积压、运行时长和最近成功时间。运行超过 90 秒的任务标记为“超时风险”；同一资源不能同时出现两个有效 owner。结束或租约失效后，下一次领取必须能够恢复执行，旧 owner 的结果不得写回。

## 通过条件

- 故障、采集盲区、控制失败和恢复事件分别可见。
- 未确认请求不会被统计为成功，也不会解除风险。
- 恢复只使用当前来源和当前配置代次的证据。
- 重复领取、旧 owner 写回和迟到响应均被拒绝。
- 自动动作的前后值、观察窗口和最终效果状态可追溯。
- 演练结束后关闭自动写回，删除演练数据库和本地密钥。

演练结果应记录提交号、数据库隔离标识、开始/结束时间、注入动作、页面证据和未通过项目；本地模拟器通过不代表生产 SLA。
