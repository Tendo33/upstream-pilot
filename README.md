# Sub2API Upstream Manager

面向自建 Sub2API 的上游质量与成本管理工具。

目标是保持用户分组的服务稳定：持续发现上游首字变慢、503、余额不足和价格上涨，并根据明确的规则调整优先级，保留可用备用渠道。

## 当前状态

已初始化本地 Git 仓库。业务代码、界面和部署配置尚未实现，也尚未引入上游项目源码。

## 首版范围

- 同步 Sub2API 的上游账号、模型与分组关系。
- 按账号和模型探测，记录首字延迟、总耗时、流式完成状态与失败原因；结合真实请求数据评估质量。
- 采集上游余额、倍率及价格变化，并保留采集时间与历史值。
- 持续变慢、错误增多或成本上涨时降低优先级，保留为备用。
- 恢复后经过连续验证，逐步恢复优先级。
- 展示分组整体质量、备用情况与每次自动调整的原因。
- 提供故障、恢复、低余额和价格变化通知。

## 默认策略

- 支持仅观察与自动调整两种模式，初始使用仅观察模式。
- 自动调整默认只写回 `priority`；停用与恢复调度使用独立开关。
- `concurrency`、`load_factor`、用户分组售价不随质量策略自动修改。
- 只允许一套策略统一决定并写回账号优先级，避免不同自动任务相互覆盖。
- 保存人工基准值和本工具最后写入值；发现人工修改时，不盲目覆盖或还原。
- 单次失败不立即认定持续故障；限流、余额不足、认证失效、网络异常分别处理。
- 数据缺失或过期标记为未知；余额与价格采集失败不能当作余额为零或价格下降。
- 每次调整记录原因、前后值与写回结果，支持停止接管。

## 实现方向

计划基于 [S2AM-GO](https://github.com/langrenjh-alt/S2AM-GO) 的账号管理、余额和倍率采集能力开发，补充首字检测、质量降级和恢复策略。技术方向为 Go、React 和 PostgreSQL。

[Sub2API Guardian](https://github.com/codermyxiaoc/sub2api-guardian) 作为功能研究参考。S2AM-GO 的 MIT 许可在引入源码时一并保留；Guardian 的源码复用许可尚未确认，当前不引入其代码。

## 接入边界

工具通过 Sub2API Admin API 同步与调整账号。请求转发、请求内超时与安全故障切换由 Sub2API 执行。

同一账号跨多个分组时，账号级 `priority` 会影响所有所属分组，策略需要统一处理。优先级调整的实际效果还受线上版本、调度配置和会话绑定影响，接管前需验证。

后续先完成定向探测和仅观察面板，再验证自动优先级调整。
